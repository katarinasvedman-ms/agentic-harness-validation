The high-level pitch

Agents should be powerful—without becoming unpredictable systems.

Enterprises want agents that do real work, not just answer questions. The challenge is giving them autonomy while preventing tool misuse, data exfiltration, privilege escalation, and unsafe production changes.

The technical pitch

A probabilistic loop inside a deterministic control plane.

Each technology has one clear responsibility. There is one inner agent loop, two enforcement points, and multiple independent safety boundaries.

Host Foundry Hosted Agent

Managed endpoint, container runtime, session isolation, agent identity, scale, and platform telemetry.

Compose Microsoft Agent Framework

Outer agent abstraction, application workflow, and future multi-agent composition.

Reason GitHub Copilot SDK

The inner reason-act-observe loop: context, turns, tools, streaming, sessions, and events.

Govern Verified plan + AGT

Formal plan invariants, pre-tool policy, exact approval, kill switch, and action budgets.

Execute Governed tool gateway

Revalidates policy, approval, digest, identity, idempotency, and scope before side effects.

Critical design choice: Copilot owns the inner tool loop. Agent Framework does not run a competing loop, and ordinary middleware is not the sole enforcement point. Every action is checked in OnPreToolUse and checked again at the gateway.

Defense in depth

No single control carries the whole burden.

The design assumes models can be influenced and components can fail. Independent controls overlap so one mistake does not automatically become an incident.

P

Pre-tool policy

AGT evaluates a trusted action envelope before the Copilot tool handler can run.

V

Verified plan gate

Dafny-backed invariants cover declared capabilities, approvals, dependencies, data flow, and state transitions.

H

Exact human approval

Approval binds to one immutable action digest, resource, environment, expiry, and single-use nonce.

G

Gateway revalidation

The execution boundary recomputes the digest and repeats policy, approval, budget, and kill-switch checks.

I

Identity and RBAC

A dedicated Entra agent identity receives only the permissions required for the bounded demo.

O

Observability and audit

Turns, decisions, approvals, proofs, and side effects share one correlated trace and durable evidence trail.

Honest assurance

Precise claims build more trust than broad promises.

What we can demonstrate

  • Unauthorized tools are structurally denied before execution.
  • Production writes require an exact, current approval.
  • Selected plan and workflow invariants are formally verified.
  • Every action is attributable to identities, versions, and policies.
  • Safety regressions can block deployment.

What we do not claim

  • That the model or complete distributed system is formally verified.
  • That proof can compensate for an incorrect specification.
  • That evaluations alone establish safety.
  • That preview or experimental components are already production-certified.
  • That a simulated demo proves readiness for an unrestricted production API.

The model may be unpredictable. The system does not have to be.
